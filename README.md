# Календарь

Личный календарь-планировщик: неделя/день со шкалой времени, разовые и циклические задачи, отметки «сделано» по каждому дню. Вход по одному паролю, без базы данных — все данные лежат одним JSON-файлом в приватном Vercel Blob.

## Локальный запуск

```bash
npm install
npm run dev
```

Пароль локально — `dev` (или `APP_PASSWORD` из файла `.env`, см. `.env.example`).
Данные локально пишутся в `.local-data/calendar.json`, Vercel Blob не нужен.

```bash
npm test        # тесты логики повторений и API
npm run build   # проверка типов + сборка
```

## Деплой на Vercel

1. Залейте проект на GitHub и импортируйте его в Vercel (**Add New → Project**). Framework определится сам (Vite), настройки сборки менять не нужно.
2. В проекте откройте **Storage → Create Database → Blob**, доступ — **Private**, подключите к проекту (все окружения). Vercel сам добавит переменную `BLOB_READ_WRITE_TOKEN`.
3. **Settings → Environment Variables** → добавьте `APP_PASSWORD` — это ваш пароль для входа. Делайте его длинным: сайт публичный, ограничения попыток входа нет.
4. **Deployments → Redeploy**, чтобы переменные подхватились.

Сменить пароль = поменять `APP_PASSWORD` и сделать Redeploy. Все устройства при этом разлогинятся.
Необязательно: `AUTH_SECRET` — отдельный секрет для подписи токенов (по умолчанию используется сам пароль).

## Как это устроено

- `src/` — SPA на React. Повторы не размножаются в данных: `src/lib/recurrence.ts` вычисляет вхождения на видимый период.
- `api/login.ts` — сверяет пароль с `APP_PASSWORD`, выдаёт подписанный токен на 30 дней.
- `api/data.ts` — `GET`/`PUT` всего календаря, только с валидным токеном. Файл `calendar.json` лежит в приватном Blob и напрямую по ссылке недоступен.
- `api/_lib/core.ts` — общая логика API; в `npm run dev` она же работает через middleware в `vite.config.ts`.
- В браузере данные кэшируются в localStorage: страница открывается мгновенно, изменения уходят на сервер через ~1 с (индикатор в шапке). При возврате на вкладку подтягиваются изменения с других устройств. Конфликты решаются по принципу «последняя запись побеждает».
